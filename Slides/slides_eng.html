Intelligent Line Follower — Test Protocol

Intelligent Systems and Robotics Laboratory (ISRLAB) — A.Y. 2025/26

CoppeliaSim Simulation · Hybrid deliberative-reactive architecture (Behaviour Tree)
Supervisor: Prof. Giovanni De Gasperis

Robot at a glance

VISION SENSORS (×5, downward-facing, binary)

  • LeftSensor — left deviation
  • MiddleSensor — centre + RGB colour reading
  • RightSensor — right deviation
  • InternalLeft/RightSensor — fine drift correction

PROXIMITY SENSORS (×3)

  • Central / Left / Right — threshold 0.20 m

ACTUATION

  • Differential-drive: 2 wheels, DOF = 2
  • Velocity control: setJointTargetVelocity
  • Base speed (move/rotate): π rad/s

MOTION MODES (MotionMode)

  • LINE_FOLLOW · WALL_FOLLOW
  • REACH_ITEM · EXIT

Vision binary threshold: 0.5 on packet index [10]. Black line ≈ 0.0–0.3 → True (line); white floor ≈ 0.7–1.0 → False.

Three-layer architecture

  • Sensing — readsensor.py in sysCall_sensing: reads all 5 sensors, applies threshold, broadcasts sensor_reading and proximity.
  • Reactive — actuatormotor.py in sysCall_actuation: BT tick, dispatch to motion primitive, STOP handling.
  • Deliberative — Behaviour Tree (py_trees) + shared Blackboard.

BLACKBOARD — key entries

  • motion_mode, vocal_cmd, current_behaviour
  • obstacle_detected[3], obstacle_distance[3]
  • item_picked, item_reached, exit_reached

Decoupled message bus: broadcastMsg() / sysCall_msg().

All 16 test cases verify sub-goals and transitions of this state machine.

1Sharp corners

LINE_FOLLOW5 vision sensors
  • The robot follows the black line through sharp-edge corners (abrupt direction changes).
  • When the line leaves the centre zone, outer-sensor recovery kicks in with outer rotation factor 1.5 (aggressive edge recovery).
  • Line lost left → rotate left; lost right → rotate right, until reacquired.

Pass: the robot reacquires the line after the corner without leaving the track.

2Smooth curves

LINE_FOLLOWInternal sensors
  • Gentle, continuous bends: steering is governed by the internal sensors (Internal Left/Right).
  • Fine anti-drift correction with factor −1.1011: slight wheel differential to stay centred.
  • No sharp rotations: motion remains forward (cruise π rad/s).

Pass: smooth tracking, minimal centring error throughout the curve.

3Tight sharp corners

LINE_FOLLOWOuter recovery
  • Small-radius edges: the line leaves the inner sensor field quickly.
  • Outer sensors engage a rotate-in-place manoeuvre (factor 1.5) to latch onto the tight corner.
  • Stress test for the balance between forward speed and rotation speed (rad_rot = π).

Pass: the robot completes the tight corner without permanently losing the line.

4Tight smooth curves

LINE_FOLLOWInternal + outer
  • Smooth but small-radius bends: require continuous and increasing correction.
  • Starts with fine inner correction (−1.1011); if deviation grows, outer recovery (1.5) takes over.
  • Verifies the gradual transition between fine correction and aggressive recovery.

Pass: continuous tracking of the tight curve without excessive oscillation.

5Intersections ignored

LINE_FOLLOWRobustness
  • At intersections the robot does not deviate: it holds its current direction.
  • "Hold last direction" logic: when all sensors see line/ambiguity, the heading is maintained for ~50 ms.
  • Prevents an intersection from being misinterpreted as a curve.

Pass: the robot crosses the intersection going straight on the main line.

6Obstacle avoidance

WALL_FOLLOWProximity < 0.20 m
  • Cup-shaped obstacle detected: a proximity sensor drops below 0.20 m.
  • Transition LINE_FOLLOW → WALL_FOLLOW: bang-bang wall-following bypass at speed wf_base_speed = 3.5.
  • Once past the obstacle (proximity clear), returns to the previous mode and reacquires the line.

Pass: navigates around the obstacle maintaining clearance and re-enters LINE_FOLLOW.

7Roundabout → pick up → finish line

REACH_ITEMgreen = left entryyellow = right entry
  • Follows the line, enters roundabout: green marker (left) or yellow (right) → choreographed 4-step steering sequence.
  • Picks up the object and carries it toward a finish line placed outside the roundabout.
  • Roundabout steer: base π×2.0, differential π×1.4, micro-steer 0.35 s, colour cooldown 1.0 s.

Pass: 4 steering steps executed, object picked up, correct exit toward the finish line.

8Finish line → roundabout → pick up → return

REACH_ITEM → EXIT
  • Crosses the finish line (marker) first, then executes the roundabout.
  • On exit, picks up the object, performs a 180° U-turn (14.0 rad/s, ~0.224 s), re-enters the roundabout.
  • State sequence: marker detected → REACH_ITEM → red marker → EXIT → return to finish line.

Pass: full cycle with U-turn and return to the finish line point.

9Pick up inside roundabout → return

REACH_ITEM → EXIT
  • Follows the line, crosses the finish line; picks up the object while navigating inside the roundabout.
  • Completes the roundabout; a few seconds after exiting performs the U-turn, re-enters and returns to the finish line.
  • Flags involved: item_picked (picked) → item_reached (red) → exit_reached.

Pass: pickup executed during the roundabout and correct return to the finish line.

10Return only if finish line reached

REACH_ITEMno red marker
  • Does the roundabout and picks up the object inside, but keeps wandering on the line.
  • Demonstrates the precondition: the return U-turn happens only after reaching the finish line (red marker).
  • Doc case "Pickup active, no red marker": completes the full lap without U-turn.

Pass: no U-turn until the finish line has been reached.

11Lost line search + timeout

LINE_FOLLOWAll sensors white
  • All 5 sensors white (no line): holds the last direction for ~50 ms, then rotates to search for the line.
  • "Random" search (rotation) until the track is reacquired.
  • If nothing is found within the timeout → stops (safety state).

Pass: line reacquired, or controlled stop after timeout.

12Voice command: fixed-side avoidance

WALL_FOLLOWswitch_lf / switch_ms-like
  • Voice command that forces the robot to bypass all obstacles to the right or all to the left.
  • The command updates the blackboard (vocal_cmd) → the bang-bang always chooses the same side.
  • Communication via message bus / topic robot/commands/*.

Pass: every obstacle is bypassed on the side dictated by the voice command.

13Voice command: stop / start

stop_signalresume_signal
  • "stop" command: current_behaviour = STOP → motors halt immediately in the dispatcher.
  • "start" command: restores the previous motion mode and resumes.
  • Topics: robot/commands/stop and robot/commands/resume.

Pass: immediate halt on "stop", coherent resume on "start".

14Following_Mode (ignores mission)

pure LINE_FOLLOW
  • In Following mode the robot ignores the finish line and the object: pure line following only.
  • Blue/red markers do not trigger REACH_ITEM or EXIT.
  • Matches the doc case "Full lap, no markers": completes the closed loop.

Pass: full lap of the track without activating any mission logic.

15Mission_Mode (executes mission)

REACH_ITEM / EXIT active
  • In Mission mode the robot reacts to the finish line and the object.
  • Blue marker → finish_line=True, REACH_ITEM; red marker → EXIT + 180° U-turn; back to blue → stopSimulation().
  • Executes the full pickup & delivery chain.

Pass: complete mission: pickup, delivery, U-turn and clean stop.

16Voice switch Follow ↔ Mission

switch_lf_signalswitch_ms_signal
  • Voice command that switches from Follow_Line to Mission_Mode and back.
  • Topics: robot/commands/switch_lf and robot/commands/switch_ms → updates motion_mode on the blackboard.
  • Verifies that the behaviour actually changes between the two modes (TC14 vs TC15).

Pass: after the switch the robot correctly transitions from "ignore mission" to "execute mission".
